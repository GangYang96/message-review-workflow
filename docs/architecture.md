# 报文复核工作台

- `src/core.js`：支持两类键值报文，提取来源行并检查必填字段、冲突值与修订依据。
- `src/workflow.js`：创建记录、状态转换、版本检查、历史重放及批量处理。
- `web/app.js`：工作台页面模板。
- `web/workbench.js`：队列、表单、来源定位、本机保存和导入导出。
- `scripts/review.cjs`：兼容原单笔 CLI；`scripts/batch.cjs`：新版批量与存档 CLI。

## 状态转换

`review → approved / returned → review`

修订只能发生在 review 状态；确认要求复核人和通过字段检查；退回要求复核人及原因。approved 和 returned 不接受直接修改，必须通过 reopen 并记录原因。重新复核清空当前说明，旧说明继续存在于历史。每次转换检查预期版本号并产生下一版本，不修改传入对象。

## 存档格式

存档包含 `schema_version: 1`、`kind: message-review-queue` 和 records。每条记录只保存 id 和事件列表；导入时从第一条原文重放后续事件，不信任外部提供的终态。校验事件版本连续、时间不倒退、转换合法及事件内容一致。

限制：100条记录、单条原文30,000字符、每条500个事件、待办包5 MB。字段最长200字符、复核人60字符、说明2,000字符。导入失败保留当前队列。

## 保存和冲突

只有“保存到本机”写入 localStorage，键为 `gang-yang-message-queue-v1`。保存前比较上次读取的原始值；发现另一标签页修改则拒绝覆盖，提示先导出并刷新。浏览器禁用存储或容量不足时显示错误，当前内存记录仍可导出。未保存修改在离开时触发浏览器提醒。

这是单机演示的冲突保护，不是数据库事务；两个标签页在极短时间内同时检查和写入仍可能竞争。复核人是用户输入文本，本机历史没有身份认证、签名或防篡改保证，不应作为生产审计证据。当前解析器不接入 HiAgent 或真实银行报文网络。
